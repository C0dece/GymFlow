# GymFlow Markdown v1

В каждом файле указан YAML frontmatter с `gymflow_schema`, `id` и `kind`. Для сессии добавляются дата ISO 8601, статус и UUID участников. Имя нового файла формируется по UUID. Импортированную запись можно узнать по UUID даже после перемещения файла в пределах поддерживаемых каталогов.

Сущности `session`, `program`, `exercise` и `profile` имеют отдельные файлы. Пример тренировки находится в [эталонном файле](../app/src/test/resources/golden/session-v1.md).

## Канонические данные

Канонический JSON расположен в комментарии между строками `<!-- gymflow:json` и `gymflow:json -->`. Kotlin Serialization проверяет структуру. YAML отражает метаданные, а отчёт между маркерами `gymflow:report` генерируется из модели. Ручные заметки храните вне обоих служебных блоков, например между отчётом и JSON. При пересборке отчёта эти заметки сохраняются. Дополнительные свойства YAML поддерживаются в однострочной записи.

| Сущность | Содержание |
| --- | --- |
| Сессия | UUID, дата, статус, снимки участников, упражнения и их предыдущие замены, начало и завершение, заметки и показатели каждого участника. |
| Упражнение | UUID, название, тип нагрузки, единицы, диапазон повторов, избранное, архив и необязательные данные каталога. |
| Программа | UUID, дни по порядку, недельное расписание или гибкий цикл, общий план подходов и индивидуальные планы по UUID. |
| Профиль | UUID, имя, оттенок и компактность. История и статистика связываются по UUID участника. |

Каждый подход хранит исходный план, статус и отдельный необязательный результат. Снятие галочки переводит подход в Planned и сохраняет ранее введённый результат. В фактический объём входят подтверждённые рабочие подходы. Гантели хранят массу одной гантели, а объём учитывает обе. Для собственного веса сохраняется добавочная нагрузка с отдельной трактовкой. Статус сессии: Planned, Active, Completed или Skipped.

RIR хранится по участнику и упражнению как `null`, 0, 1, 2, 3 или 4, где 4 обозначает 4 и больше. Метрики участника включают массу тела в кг, кардио в минутах, самочувствие и заметку. Длительность рассчитывается из сохранённых отметок начала и конца.

## Миграции и конфликт

Интерфейс `DocumentCodec` отделяет хранилище от формата. Версия 0 тестирует миграцию поля `type` в `kind` и `name` сессии в `title`. Миграция применяется при чтении. Следующее явное сохранение пишет v1. Повреждённый JSON и неизвестные версии остаются в исходном файле, а приложение сообщает о проблеме. Свободно оформленные заметки Obsidian без маркеров GymFlow игнорируются.

Room фиксирует новую версию до обращения к SAF. Перед перезаписью приложение сравнивает SHA-256 файла с ожидаемой версией и сохраняет предыдущий текст. После записи оно перечитывает файл и подтверждает хеш. При обнаружении изменений локальная версия и внешний документ доступны для выбора. Из настроек можно выгрузить архив с текущими записями и доступными резервными копиями.

Состояние отделено по URI выбранной папки. При первой привязке записи локального режима копируются в выбранное хранилище. Версию прежней папки можно снова открыть, выбрав её в настройках. Формат рассчитан на UTF-8, ограничение одного входного файла составляет 512 КиБ.
