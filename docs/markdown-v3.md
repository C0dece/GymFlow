# GymFlow Markdown v3

Версия 3 расширяет [Markdown v2](markdown-v2.md). Канонический JSON хранится внутри комментария `gymflow:json`. YAML содержит версию, вид документа и UUID. Отчёт для чтения в Obsidian строится из JSON. Свободные заметки и пользовательские поля YAML сохраняются.

## Прогрессия

- `progression_policy` хранит UUID и версию настройки, область, блокировку, стратегию, ограничения, волны и правила. У правила есть UUID, версия, имя, приоритет, типизированные условия и действие. Условия одного правила соединяются через «и».
- `progression_review` хранит решения после завершения участника или всей сессии. Связи используют UUID сессии и профиля. Длинные списки решений разбиваются на части с устойчивыми UUID.
- У сессии `progression` содержит снимок предложения, решение пользователя и итоговый план. У подходов `actual` хранит измерения. `targetReps` задаёт цель внутри диапазона `repsMin..repsMax`.
- Для одного участника сопоставляются UUID упражнения и тип нагрузки. Названия, порядок упражнений, дни недели и наборы упражнений в других сессиях могут меняться.
- Приоритет идёт от предупреждения о дискомфорте к явной блокировке, связке «упражнение + участник», упражнению, участнику, программе и общим настройкам. В активной области учитываются правила с наибольшим приоритетом. Противоречивые действия одинакового приоритета дают удержание с объяснением.
- Двойная прогрессия повышает вес после подтверждения верхней границы всех рабочих подходов и остальных условий. Увеличения требуют пригодной истории и подтверждённой текущей нагрузки. Учитываются запас повторений, пропуски и доступные шаги оборудования. Разминки сохраняют исходные параметры.
- При повторном выборе неизменённого шаблона расчёт может продолжить нагрузку из подтверждённого плана той же пары участника и упражнения. Вес или повторы в черновике меняются по выбору пользователя.

## Совместимость и восстановление

Чтение поддерживает схемы от 0 до 3. При первой записи в новой схеме сохраняется исходный файл в приватной папке приложения. Эти копии входят в экспорт резервного архива. Для цветов понимаются числовой ARGB, RGB/ARGB HEX и десятичные строки. Отсутствующий, повреждённый или неизвестный цвет использует оформление по умолчанию. Старые файлы с экранированным знаком минуса в числах восстанавливаются при чтении.

Room хранит локальный журнал ожидающих операций. При потере доступа SAF изменения остаются в журнале и доступны для экспорта. Повреждённая запись изолируется. Исходное содержимое доступно при восстановлении или в резервном архиве.
