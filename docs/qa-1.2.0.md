# GymFlow 1.2.0

## Сбой при смене цвета

В версии 1.1.0 чтение профиля ожидало JSON-число `Int`. В контролируемом воспроизведении на Android Emulator запись Room со старым Markdown и цветом `"#CF91EA"` привела к `JsonDecodingException` на `$.color` и завершению процесса при открытии журнала. Установка новой сборки поверх старой открыла журнал с той же записью. Содержимое исходной пользовательской заметки не проверялось.

Регрессия записи выявила второй путь к повреждению данных. Старый Markdown-кодек экранировал все дефисы, включая минус в отрицательном ARGB-числе, которое выдаёт палитра. Так формировался синтаксически неверный JSON. Запись теперь экранирует только закрывающий маркер комментария. Чтение восстанавливает минус в старых числовых полях. Сериализатор принимает старые форматы цвета и применяет безопасное оформление для неподдерживаемого значения. Сохранение создаёт исходную копию перед миграцией.

## Прогрессия и сохранение

На экране «Прогрессия» можно выбрать область, стратегию, расширенные ограничения и декларативные правила с предпросмотром. Поддерживаются двойная и линейная прогрессия, повторы, объём, RIR, волны, поддержание, разгрузка и пользовательская стратегия. Автоматический режим использует двойную прогрессию. Рекомендация включает причину, рабочие подходы, фактические показатели, RIR и сработавшие правила, если они применимы.

После завершения сессии решения сохраняются для каждого участника. В следующем плане из расписания, шаблона, истории или пустого черновика можно принять предложение, сохранить исходные параметры или отредактировать вручную. Факт хранится отдельно. При расчёте учитывается хронология нескольких сессий за одну дату.

Некорректная запись изолируется при чтении. Повреждённые настройки DataStore заменяются значениями по умолчанию. В случае сброса настройки папки можно выбрать прежнюю папку заново. При недоступности SAF результаты остаются в локальном журнале Room. При восстановлении доступа запись повторяется. Резервный архив содержит исходные данные проблемных записей и копии до миграции.

## Проверки

- Финальная сборка прошла 37 JVM-тестов, 9 инструментальных тестов и 2 теста конвертера. Android Lint сообщил 0 ошибок и 9 предупреждений. Проверки AAR metadata и дублирующихся классов прошли.
- Android Emulator `GymFlow_Compact`, локальные синтетические папки SAF. Файлы Google Drive и пользовательские тренировки не использовались.
- Compose проверяет последовательную смену цветов трёх профилей, пересоздание Activity, сохранённое состояние редактора и чтение новых файлов. Отдельно проверен холодный запуск после `am force-stop`.
- В сценарии прогрессии первый план выполнен с 20 кг и RIR 2. После смены стратегии во втором плане подтверждена рекомендация 21 кг, у партнёра осталось 20 кг. Сессия сохраняет два независимых решения. После пересоздания Activity экран прогрессии отображается, пользовательское правило сохраняется через конструктор.
- Восстановление настроек проверено с заведомо повреждённым protobuf. Logcat зафиксировал `settings_corruption defaults_restored`, экран тренировок открылся в новом процессе.
- SAF проверен для конфликта, временной потери доступа, повторной записи, перезапуска Activity и сохранения оригинала перед миграцией.
- Нагрузочная проверка использует Room на эмуляторе, три профиля, каталог из 500 упражнений, 100 и 1000 синтетических сессий и 1500 решений для каждого объёма. Измеренное время чтения, статистики и расчёта составило 658 мс для 100 сессий и 2488 мс для 1000 сессий.

## Границы проверки

Использован стандартный локальный DocumentsProvider. Поведение сторонних провайдеров, физические устройства и дефект на исходной пользовательской заметке не проверялись. Стресс-тест измеряет чтение Room, Markdown и расчёт решений. Время синхронизации 1000 заметок через сторонние провайдеры не измерялось. SAF-тест воспроизводит недоступность папки и сохранение ожидающей операции через пересоздание Activity. Принудительное завершение процесса внутри операции записи SAF отдельно не моделировалось.
