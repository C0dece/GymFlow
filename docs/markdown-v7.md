# Хранилище GymFlow

GymFlow пишет Markdown v7 и читает v0-v7. В v7 заголовок, поля и таблицы содержат рабочие данные. YAML хранит версию, тип, стабильный ID и дополнительные свойства. В старых версиях основными данными был JSON в комментарии, в v7 этот блок отсутствует.

## Папки и имена

- `Программы/Силовая программа.md`
- `Тренировки/2026-11-20 - Грудь и трицепс.md`
- `Упражнения/Тяга блока.md`
- `Заметки/Цели на месяц.md`

Участники, прогрессия и движения хранятся в одноимённых папках. При совпадении имён GymFlow использует дату, участника или порядковый номер. После переименования или перемещения файла внутри подключённой папки GymFlow находит его по `id` и продолжает писать в него. Для сопоставления папки используется файл «Хранилище GymFlow.md». Старый маркер `gymflow-vault.md` тоже читается. Системные каталоги с точкой в начале пропускаются.

## Редактирование

Измените заголовок программы или тренировки после `#`. В списках можно редактировать значения, сохраняя названия полей и отступ в два пробела на уровень. У подходов данные находятся в таблицах. Столбцы `Вес`, `Повторы от` и `Повторы до` задают план, `Факт / Вес` и `Факт / Повторы` содержат результат. Вес можно вводить с точкой или запятой. Пустая ячейка пропускает поле, `Нет значения` означает отсутствие значения. У существующих записей сохраняйте ID. Для статусов годятся значения «Запланировано», «В процессе», «Завершено», «Пропущено», а также другие варианты, предусмотренные типом записи.

В программе редактируйте план в «Тренировочные дни → Упражнения → Подходы». В записи занятия меняйте рабочий план и факт в «Тренировки участников → Упражнения → Результаты участников → Подходы». Настройки программы и сохранённый результат занятия живут отдельно.

Свободные разделы добавляйте за пределами комментариев `gymflow:данные`. Текст заметки редактируется между её комментариями `gymflow:note`. Неизвестные поля в распознанных записях и дополнительные свойства YAML сохраняются при записи. Повреждённая структура остаётся в папке, а GymFlow показывает ошибку и сохраняет локальную копию. При одновременных изменениях доступны локальная версия и версия из папки.

Связи определяются по ID. Когда GymFlow знает пути связанных файлов, он пишет ссылки Obsidian в свойство `gymflow_links`. Переименование меняет путь ссылки, тогда как связь по ID сохраняется. При миграции известные вики-ссылки в заметках GymFlow получают новые пути.

## Миграция и откат

1. Обновите GymFlow на всех устройствах, которые используют папку, и дождитесь окончания синхронизации.
2. В настройках выберите «Перевести папку на новый Markdown» и сохраните ZIP вне подключённой папки. GymFlow проверит архив перед первой записью. Архив содержит исходники и таблицу с путями, ID и хешами до и после.
3. Миграция преобразует распознанные записи, переименует файлы с точным именем `<id>.md` и сохранит уже понятные имена. Неизвестные файлы остаются на месте. Если провайдер не поддерживает переименование, перенесите папку через локальное хранилище Android или используйте синхронизированную копию на компьютере.
4. Для отката приостановите запись и синхронизацию папки. В её локальной копии запустите скрипт сначала без `-Apply`. Он сверит хеши и покажет, какие файлы можно восстановить. При обнаружении более поздних правок скрипт остановится.

```powershell
.\scripts\restore-markdown-vault.ps1 -Vault 'Путь к папке' -Archive 'Путь к ZIP'
.\scripts\restore-markdown-vault.ps1 -Vault 'Путь к папке' -Archive 'Путь к ZIP' -Apply
```

Авторский формат импорта программ описан отдельно в [Markdown v6](markdown-v6.md).
